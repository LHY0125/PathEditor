## 二、三处待裁断的结论

### 裁断 1（B1）—— 新增 `tests/setup.ts`

**采纳。** 理由：

1. **这是既有缺口，不是 plan 引入的**：`@testing-library/jest-dom` 已在 `devDependencies`（`^6.9.1`）却从未注册，现有 17 个测试文件因此只能写 `toBeNull()` / `toBe()`。**修好它是一次性收益**，不是为本波特设。
2. **改写断言是更差的选择**：Task 2/4 里 `toBeInTheDocument()` / `toBeDisabled()` 是**语义正确**的断言（`toBeDisabled` 还会检查 `aria-disabled` 等语义），改成 `toBeNull()` 会降低表达力且更啰嗦。
3. **代价可接受**：`vitest.config.ts` 加一行 `setupFiles`，plan 文件清单补一个文件。

**注意事项**：jest-dom 匹配器**按需引入**（`/vitest` 子路径），对既有测试无副作用。改完后应跑一次 `npx vitest run` 确认 17 个既有测试文件全绿。

### 裁断 2（H1）—— 斑马纹真移除

**采纳「真移除」。** 理由：

1. **spec D1 的设计意图**：新 token 层定义了 `--app-row-even` / `--app-row-odd`，浅色模式下两者**几乎同色**（`#ffffff` / `#fafafa`），"斑马纹"在视觉上已经不存在。保留 `nth-child(odd)` 只是在**制造一个无效果但会闪烁的类**。
2. **虚拟滚动的致命问题**（开发窗口指出）：`nth-child(odd)` 基于**当前渲染的 DOM 子节点顺序**，而虚拟滚动只渲染可视窗口内的行。**滚动时奇偶判定会跳变，导致行色闪烁**。现状的 `rowIdx % 2`（逻辑索引）是正确的，必须保留这个语义。
3. **结论**：删除 `.path-row:nth-child(odd)`，改为在行渲染时用 `rowIdx % 2 === 1` 决定 `data-odd` 属性，CSS 用 `.path-row[data-odd='true']`。

> **这不是「保留斑马纹」，是「保留逻辑索引决定的交替底色，且在新 token 下它几乎不可见」。**

### 裁断 3（H5）—— `.tab-active` 记为有意偏离

**采纳「记为有意偏离」。** 理由：

1. **原值是硬编码 `#3b82f6`**，在深色玻璃主题下与 `--app-accent: #7c6cff` 不协调。
2. **spec H3 的裁断原意是「不改 `.tab-active` 的规则结构」**（防止波及对话框布局），而非「连它的色值都不能碰」。把硬编码色换成语义变量**不改变结构**，且**自动获得双主题适配**。
3. **净改进**：浅色下 `--app-accent` = `#6366f1`（与 `#3b82f6` 视觉接近），深色下 = `#7c6cff`（比原 `#3b82f6` 对比度更好）。

**裁断**：保留此改动，在 spec 中记为**有意偏离**，注明理由。

## 四、审核窗口自省（第二次）

本轮暴露的**两个实质性失职**：

| 失职                       | 性质                       | 根因                                                                                                                                            |
| -------------------------- | -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **B2**：Task 9 断言会假绿  | **写了一条永远为真的断言** | 我写 `overflow: hidden` 的同时写了「检测文档溢出」的断言——**这两个设计互相抵消，而我写的时候没意识到**。断言设计与样式设计必须交叉审查          |
| **B3**：声称已修、实际未修 | **只改了描述，没改代码块** | 我修 `menu.darkMode` 时改了三处文字说明（Interfaces / NEW_KEYS / 说明），**唯独漏了两个 JSON 代码块**。这是「改了文档的元数据，没改文档的实体」 |

> **两条教训合并成一条**：**验证必须作用于最终产物，而不是作用于「我以为我改了的地方」。**
>
> B2 的教训：**断言的失效往往来自产品代码本身**（`overflow: hidden`），而非断言的写法。审查断言时，必须连同它要检测的样式一起看。
>
> B3 的教训：**「已修」的判据是 `grep` 结果为空，不是「我改了说明」。** 开发窗口用 `grep` 找到了残留，而我凭记忆认为已修。
