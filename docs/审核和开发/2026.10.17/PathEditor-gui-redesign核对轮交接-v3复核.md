## 2. V3 二次修正：审核窗口是对的，我上一轮的说法也不准确

### 审核窗口的修正

裁断 §二 说：`tests/unit/app-shell-env-vars.test.tsx:193-203` **也不是**假绿风险，因为该用例同样在 `allVars` 分支下运行，`ToolBar` 根本不渲染。

### 开发窗口独立验证：**成立**

```tsx
// tests/unit/app-shell-env-vars.test.tsx:193-203
it('「全部变量」下 PATH 专用按钮不可见', async () => {
  render(<AppShell />);
  fireEvent.click(screen.getByText('全部变量'));   // ← 切到 allVars
  ...
  expect(screen.queryByRole('button', { name: '导入' })).toBeNull();
  expect(screen.queryByRole('button', { name: '导出' })).toBeNull();
});
```

`AppShell.tsx:173` 是 `activeTab === 'allVars' ? <EnvVarToolbar/> : <ToolBar/>`。**切到 allVars 后 ToolBar 不在 DOM 里**，所以这 5 条断言测的是「allVars 分支不渲染 ToolBar」，与 ToolBar 内部布局无关。

**我上一轮把它称为「真正的同类风险」是不准确的**——它同样不会假绿。审核窗口的修正正确。

### 但裁断给出的**准确表述**仍有一处措辞可再收紧

裁断 §二 结尾：

> 存在的是「**跨分支断言无法检出按钮搬家**」……正确的应对不是改这些断言，而是**在主行场景下新增一条断言**：`crud-undo` / `import-export` 等已有的主行用例会覆盖「导入/导出可见」，这已经够了。

**独立验证「已经够了」这一主张**：

```ts
// e2e/tests/import-export.spec.ts:9-16
test('导出按钮可见', async ({ page }) => {
  await expect(page.locator('text=导出')).toBeVisible();
});
test('导入按钮可见', async ({ page }) => {
  await expect(page.locator('text=导入')).toBeVisible();
});
```

✅ **成立**。这两条在默认（系统 PATH）tab 下运行，`text=导出` 是**子串匹配**，若按钮被移进未展开的菜单则 `toBeVisible()` 失败。**「导入/导出搬家会被检出」有现成覆盖，无需新增断言。**

> **但注意一个不对称**：「上移/下移/一键清理」**��有**对应的主行可见性断言（`search-clean.spec.ts:45` 是**点击**而非**可见性**断言，且它自己就在「必须改」清单里）。所以这三个按钮搬家后，**唯一的检出手段就是那条会红的点击用例**——这已经足够，但值得在 plan 里知道：**它们没有冗余保护**。
