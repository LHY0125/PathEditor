## 2. P1 修复证据

### 修复前

```rust
#[test]
fn backup_registry_default_dir_no_panic() {
    // 验证不传参时不会 panic
    let _ = backup_registry(None);
}
```

**两个缺陷**：① 无隔离 → 写用户真实备份目录，且**触发 20 份轮换**（每次跑测试都可能**挤掉一份真实备份**）；② `let _ =` 丢弃返回值 → 注册表不可读时也「通过」，**实际什么都没验证**。

### 修复后

改用同文件既有的 `with_temp_backup_dir`（重定向 `PATHEDITOR_BACKUP_DIR` + 进程锁 + 清理），并把测试重命名为 `backup_registry_default_dir_uses_redirected_dir_without_panic`：

- **可读注册表**：断言返回的备份路径 **`starts_with(隔离目录)`** 且文件存在；
- **不可读**：断言**不 panic** 且错误信息非空（注释说明为何可能失败）。

### 决定性验证（重命名法，非计数）

```
移走真实目录 ~/.patheditor/backups → 跑全量 core 测试（227 passed）
→ 真实目录【未被重建】 ✅
→ 还原，文件数 29 完好
```

> **判据说明**：用「隔离目录能否从无到有重建」而非「文件计数」——后者在 20 份轮换上限下是**饱和值**，净数量恒定会掩盖写入（本次回归中曾因此误判一次）。

**修复前**同法会重建目录并写入文件。
