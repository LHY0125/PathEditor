## 二、更正：真机回归阻塞的**根因不是陈旧条目**

开发窗口回执 §5.3 诊断「`merge_hive` 把陈旧条目并入 → expected 11 ≠ current 10」——**审核窗口复现后判定此诊断不成立**：

### 2.1 事实

- 开发窗口数的是**原始快照文件**（`userSnapshot` 11 条），**不是 `merge_hive` 的输出**。
- `merge_hive`（`core/src/disabled.rs:137-151`）的 `else if !entry.enabled`（**:148**）**丢弃**「启用但已不在注册表」的条目。陈旧条目 `Scoop\apps\git\current\cmd`（`enabled: true`、不在注册表）**被丢弃**，**未并入**。
- 实际 `merge_hive` 输出 = **10 条**（与注册表**同一集合**）。

### 2.2 真实根因：**顺序**

|                    | 顺序                                                                                                        |
| ------------------ | ----------------------------------------------------------------------------------------------------------- |
| 注册表（10，实测） | `uv\tools\shims, uv\python\shims, bun, maven, .claude\bin, npm, gsudo, Scoop\shims, VS Code, DockerDesktop` |
| 快照合并（10）     | `.claude\bin, npm, DockerDesktop, gsudo, maven, bun, Scoop\shims, uv\python\shims, uv\tools\shims, VS Code` |

**同一集合、不同顺序。** `check_expected`（`core/src/service.rs:195`）`if &current != expected` 是**顺序敏感**比较 → 失配 → 拒绝。

### 2.3 这是一个**既有死锁 bug**（非本波引入，但比「陈旧数据」严重）

- **触发条件**：任何**外部重排** PATH（本例：Scoop 在快照（Sep 20）之后重写 PATH）。
- **后果**：保存**永久被拒**。拒绝 → 存不了 → 快照永不更新 → 一直拒绝。
- **「请重新加载后重试」是假解药**：reload 走同一条 `merge_hive`，产出**同一个快照顺序**，照样失配。
- **用户影响**：**本机目前用 PathEditor 存不了 PATH**（GUI 与 CLI 同一校验）。
- **A/B 已由开发窗口坐实**（HEAD `9f9c0d8` 复现）——**非本波引入**，裁断采纳该结论。
