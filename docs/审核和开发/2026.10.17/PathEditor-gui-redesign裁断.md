### 后果定性（同意开发窗口）

> **这不是「视觉暂时不一致」，是功能受损。**

`var(--app-list-bg)` 在变量未定义时**整条声明失效**（CSS 自定义属性无回退值 → `background-color` 回到 `initial` = `transparent`）。对话框的输入框、面板底色会**变透明**，在深色模式下直接导致文字与背景不可辨。

### 裁断

**采纳方案 A。** 具体做法：

```css
/* globals.css 重写后保留这一段，作为 Wave 4.1 前的过渡别名 */
:root {
  /* 旧变量 → 新语义层。仅为 R7 范围内（对话框）不坏而保留。 */
  --app-list-bg: var(--app-surface);
  --app-list-alt: var(--app-row-odd);
  --app-hover: var(--app-hover); /* 语义不变，直接保留 */
  --app-border: var(--app-border); /* 语义不变，直接保留 */
  /* 其余旧变量（--app-fg / --app-bg / --app-select-row）同理 */
}
```

**三条附加约束**：

1. **别名必须写 `:root` 且不随 `.dark` 变化** —— 因为新语义变量本身已按主题切换，别名只需转发。
2. **在 `globals.css` 顶部加显式注释**：`// TODO(Wave 4.1)：以下为过渡别名，对话框重做后删除`。**不得静默遗留**。
3. **Wave 4.1（对话框重做）的验收标准之一**：`grep -rn -- '--app-list' src/components/dialogs` 结果为空。

### 对 spec 的修正

**§设计 Token 表**的「迁移要求」段落后补充：

> **过渡别名（R7 必需）**：`--app-list-bg` / `--app-list-alt` / `--app-hover` / `--app-border` / `--app-fg` / `--app-bg` / `--app-select-row` **全部保留为过渡别名**，指向新语义层。原因：对话框（R7 范围外）仍有 14 处引用，直接删除会导致透明底色。别名在 Wave 4.1 对话框重做时一并清理。

> **这正是不对称的来源**：spec 对 `buttons.ts` 安排了「保留旧导出名做过渡别名」，对 CSS 变量却没有同样安排。**同一把尺子要量两次。**

## 三、B2 — `toggle-save.spec.ts` 会被 D5 打断

### 复核

`e2e/tests/toggle-save.spec.ts:19`：

```ts
await page.click('text=确定'); // 工具栏保存按钮，不是对话框
```

该用例流程：勾选禁用 → 断言删除线 → **点工具栏「确定」保存** → 断言「保存成功」。

D5 把工具栏按钮改为「保存」后，`text=确定` **找不到目标**，用例必红。

### 裁断

**采纳。** R3 结论修正：

| 原结论                                          | 修正后                                                                                                        |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 「12 处 `'确定'` 断言全部指向对话框，不受影响」 | 「**12 处不受影响**（对话框，`button.save` 不变）+ **1 处必须改**（`toggle-save.spec.ts:19` → `text=保存`）」 |

**补充**：这一处改动**不是 R3 的「消解」失败，而是 R3 的范围划定有漏**。开发窗口的核实方法（逐条看断言指向哪个元素）是对的，只是少看了 `e2e/tests/` 下**除 `env-vars.spec.ts` 之外**的文件。这正是 **H1** 暴露的同一个盲区——**spec 只扫了 `env-vars.spec.ts`，没扫全部 E2E**。

## 四、B3 — `浏览...` 无归属

### 复核

`ActionButtons.tsx:39-41` 确有第 7 个按钮 `t('button.browse')` → `onBrowse`。spec 的 D2 分层表只列了 6 个（新建/编辑/删除/上移/下移/撤销/重做 —— 实为 7 个，含撤销重做；浏览缺位）。

### 裁断

**采纳，归入 ⋯ 菜单的「编辑」分组**，理由：

1. **`浏览...` 是文件选择器入口**，语义上依附于「新建路径」——新建时要选目录。但它**不是每轮必用**（可直接粘贴路径），不配占主行格子。
2. **放主行会让 800px 余量归零**（B3 若放主行，中文「浏览...」4 字符、英文 `Browse...` 9 字符，直接压垮 D4 的简写收益）。
3. **菜单内位置**：放在「维护」组**之前**新增一组「编辑」，或直接并入「维护」组首项。**裁断：并入「维护」组首项**，避免为单个条目新开分组。

**最终 8 个动作归属**：

| 动作                           | 归属                      |
| ------------------------------ | ------------------------- |
| 新建 / 编辑 / 删除             | 主行·编辑组               |
| 上移 / 下移                    | 主行·排序组               |
| 撤销 / 重做                    | 主行·撤销组               |
| **浏览...**                    | **⋯ 菜单·维护组首项**     |
| 导入 / 导出                    | 主行·批量组               |
| 保存                           | 主行·右端强调             |
| 清理无效 / 冲突分析 / 配置方案 | ⋯ 菜单·维护组             |
| 深色模式 / 语言 / 帮助         | ⋯ 菜单·应用组             |
| 取消并关闭                     | ⋯ 菜单·底部（分隔线隔开） |

## 五、三项高风险的裁断

### H1 — E2E 受影响面（**采纳并加重**）

**开发窗口报 5 个文件，审核窗口复核为 7 个**：

| 文件                        | 行     | 引用                        | 是否受影响                                      |
| --------------------------- | ------ | --------------------------- | ----------------------------------------------- |
| `analyze.spec.ts`           | 12     | `text=分析`                 | ⚠️ 进菜单，未展开不可见                         |
| `crud-undo.spec.ts`         | 11     | `text=新建`                 | 主行保留，**不受影响**                          |
| `env-vars.spec.ts`          | 71     | `name: '一键清理'` 计数为 0 | ⚠️ 进菜单，断言语义仍成立但**需先开菜单**才严谨 |
| **`import-export.spec.ts`** | 11, 15 | `text=导出` / `text=导入`   | 主行保留，**不受影响**                          |
| `profiles.spec.ts`          | 11     | `text=配置`                 | ⚠️ 进菜单                                       |
| `search-clean.spec.ts`      | 45     | `text=一键清理`             | ⚠️ 进菜单                                       |
| `startup.spec.ts`           | 32, 34 | `name: '新建'`              | 主行保留，**不受影响**                          |
| **`toggle-save.spec.ts`**   | 19     | `text=确定`                 | ⚠️ **B2**，文案变更                             |

**裁断**：

- **真正需要改的 E2E 文件：4 个** —— `analyze` / `profiles` / `search-clean`（进菜单）+ `toggle-save`（文案）。
- **需复核但大概率不改的：1 个** —— `env-vars.spec.ts:71`（断言「不存在」在菜单未展开时恒为真，**测试会假绿**——这条比开发窗口说的更危险，见下）。
- **不受影响的：5 个** —— `crud-undo` / `import-export` / `startup` / `keyboard` / `env-backup`。

> **⚠️ `env-vars.spec.ts:71` 是一条会「假绿」的断言**：`expect(...).toHaveCount(0)` 在按钮移进未展开的菜单后**永远为真**，即使该按钮真的渲染了。**必须改成「先展开 ⋯ 菜单，再断言 count 为 0」**，否则测试丧失意义。开发窗口的「修复方式由是否进菜单决定」判断正确，此处**加重为必须修**。

### H2 — `button.cancel` 共享 key（**采纳**）

**复核**：`t('button.cancel')` 共 3 处 —— `EditEnvVarDialog.tsx:143`、`NewEnvVarDialog.tsx:110`（对话框）、`ToolBar.tsx:62`（工具栏）。直接改值会让 2 个对话框显示「取消并关闭」。单测 `env-var-toolbar` / `app-shell-env-vars` 中相关断言会断。

**裁断**：与 D5 **同一处理模式**——新增 `button.cancelAndClose`，仅 `ToolBar.tsx` 使用；`button.cancel` 保持不变。

**通则（采纳开发窗口建议）**：

> **改任何 i18n key 的值前，必须先 `grep -rn "t('<key>')" src` 数引用点。** i18n 是全应用共享命名空间，与改硬编码字符串是完全不同的风险模型。此条写入 plan 的「通用纪律」。

### H3 — `.tab-active` 波及对话框（**采纳**）

**复核**：`.tab-active` 定义于 `globals.css:78`，被 3 处使用：

- `AppShell.tsx:163`（主 Tab，范围内）
- `EnvVarToolbar.tsx:86`（hive 过滤器，范围内）
- **`EnvBackupPanel.tsx:61`（对话框内，R7 范围外）** ⚠️

**裁断**：新建 `.tab-pill` 供主界面使用；`.tab-active` **原样保留**供对话框与 `EnvVarToolbar` 过渡使用（`EnvVarToolbar` 本波只换色，不换结构，沿用旧类即可）。
